# Stage 1 — Stripe-like Billing Simulation + Scenario Engine

## Objective

Build the deterministic synthetic billing/payment world that becomes the ground truth for every later stage.

## Domain objects

Implement typed models for:
- Customer
- PaymentMethod
- PaymentIntent
- Charge
- Refund
- Invoice
- Subscription
- Event

Use Stripe-shaped IDs and lifecycle semantics without claiming official compatibility.

## Event envelope

Support:

```json
{
  "id": "evt_...",
  "object": "event",
  "api_version": "2026-...",
  "created": 1760000000,
  "type": "payment_intent.payment_failed",
  "data": {"object": {"id": "pi_..."}},
  "request": {"id": null, "idempotency_key": null}
}
```

## Scenario engine

Build deterministic scenario injection with:
- seed
- start/end time
- affected dimensions
- severity
- expected metric effect
- causal mechanism
- ground-truth incident ID
- recovery point if applicable

Every injected incident must have a ground-truth record.

## Required scenarios

At minimum:

1. PSP authorization degradation
2. country-specific degradation
3. payment-method degradation
4. checkout regression by app version
5. subscription renewal failure
6. refund spike
7. duplicate charge anomaly
8. fraud-like spike
9. gradual degradation
10. harmless seasonality
11. small-cohort noisy anomaly
12. correlated but unrelated anomalies
13. recovery after degradation

## Ground truth

Represent:

```text
scenario_id
incident_id
start
end
root_cause
affected_cohorts
control_cohorts
expected_impact
expected_detection_window
expected_recovery
```

Ground truth must never be generated by Jev or the LLM.

## Data volume

Generate enough data to demonstrate:
- 1M+ events
- realistic background noise
- multiple simultaneous cohorts
- realistic temporal patterns

Do not send all data to Python analytics if ClickHouse can aggregate it.

## Acceptance

- deterministic seed reproduces identical dataset
- every scenario has machine-readable ground truth
- event/object relationships are valid
- no sensitive payment credentials exist
- replaying the same scenario yields identical expected outcomes
